# UdyamSetu Setup

This is the current setup and run guide. Environment values are loaded from the repository-root `.env` file by both Vite and FastAPI. Never commit `.env`.

## Prerequisites

- Node.js 20 LTS or newer
- Python 3.11 or newer
- A Supabase project
- A Groq API key for chatbot responses
- Optional for demo-quality Hindi/Marathi/English voice: a Google Colab account, a T4 GPU runtime, and an ngrok account

## 1. Create the environment file

From the repository root, copy `.env.example` to `.env` and replace placeholders. In PowerShell:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env } else { Write-Host '.env already exists; it was not changed.' }
```

Required values:

```env
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your_supabase_anon_key
SUPABASE_URL=https://your-project.supabase.co
SUPABASE_SERVICE_KEY=your_supabase_service_role_key
GROQ_API_KEY=your_groq_key
APP_URL=http://localhost:5173
API_URL=http://localhost:8000
```

`SUPABASE_SERVICE_KEY`, `GROQ_API_KEY`, and `INDIC_TTS_API_KEY` are server secrets. Do not prefix them with `VITE_`, do not place them in frontend code, and do not commit `.env`.

## 2. Configure Supabase

1. Create a Supabase project.
2. In Supabase Dashboard, open **SQL Editor**.
3. Run the contents of `SUPABASE_SETUP.sql` from this repository.
4. In Supabase Authentication, configure your local redirect URL if required by your chosen auth settings.
5. Copy the project URL, anon key, and service-role key into root `.env`.

The schema must be created before signup, profile, or onboarding persistence can work.

## 3. Install dependencies

### Frontend

```powershell
Set-Location frontend
npm ci
Set-Location ..
```

### Backend

```powershell
python -m venv backend\.venv
.\backend\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r backend\requirements.txt
```

If PowerShell blocks virtual-environment activation, run this once for the current shell and retry:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

## 4. Run the application

Use two terminals from the repository root.

### Terminal 1 — FastAPI backend

```powershell
.\backend\.venv\Scripts\Activate.ps1
Set-Location backend
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

Verify the backend without invoking a Groq request:

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

Expected result: a JSON response containing `status: ok`.

### Terminal 2 — Vite frontend

```powershell
Set-Location frontend
npm run dev
```

Open the URL Vite prints, normally `http://localhost:5173`. The backend CORS configuration also permits port 5174.

## 5. Verify a production frontend build

```powershell
Set-Location frontend
npm run build
```

Optionally preview the built frontend:

```powershell
npm run preview
```

## Chatbot setup

The FastAPI chatbot route is `POST http://localhost:8000/api/chatbot`. It needs `GROQ_API_KEY` in root `.env` for conversational answers. It also provides the safe agent-action route at `POST /api/chatbot/action` for visible form filling and dashboard navigation.

Password and PIN values are intentionally never sent through the chatbot service or auto-filled.

## Optional: Indic TTS for English, Hindi, and Marathi

The notebook `backend/indic_tts_colab.ipynb` creates a temporary authenticated Indic Parler-TTS API for demos.

1. Upload/open the notebook in Google Colab.
2. Select **Runtime → Change runtime type → T4 GPU**.
3. Create an ngrok account and copy its **ngrok authtoken** from the ngrok dashboard.
4. Run the notebook cells in order. It prints a temporary public endpoint and a generated private API key.
5. Add the printed values to the repository-root `.env`:

```env
INDIC_TTS_URL=https://your-ngrok-subdomain.ngrok-free.app/tts
INDIC_TTS_API_KEY=the_random_key_printed_by_the_notebook
```

The ngrok URL only tells UdyamSetu where the temporary server is. `INDIC_TTS_API_KEY` protects that public endpoint from unauthorized use. It is generated by the notebook; it is not the ngrok authtoken.

Important: the current repository has the notebook and environment configuration, but the backend TTS proxy/frontend audio player are still unfinished. Browser speech remains the active voice-output fallback until that integration is implemented.

Colab and the ngrok URL stop when the runtime disconnects. Update `INDIC_TTS_URL` after every new Colab tunnel, and use persistent GPU hosting before production.

## Troubleshooting

- **Frontend fails at startup with missing Supabase variables:** confirm root `.env` has both `VITE_SUPABASE_URL` and `VITE_SUPABASE_ANON_KEY`, then restart Vite.
- **Chatbot says it is not configured:** add a valid `GROQ_API_KEY` to root `.env` and restart FastAPI.
- **CORS/API connection error:** confirm the backend is running on port 8000 and the frontend is using a permitted local port.
- **Indic TTS endpoint stops working:** the Colab runtime or ngrok tunnel has expired; run the final notebook cell again and update `INDIC_TTS_URL`.
- **Supabase signup/database error:** run `SUPABASE_SETUP.sql` in Supabase SQL Editor and verify the URL/key pair belongs to that project.
